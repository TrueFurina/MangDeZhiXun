## 大赛提交材料要点

### 1. 技术亮点
- **真实数据保障**：采用用户手动确认学习完成机制，不生成模拟数据
- **三段式进度追踪**：0%未学习 → 50%学习中 → 100%已完成
- **多层防护机制**：数据库触发器 + 后端逻辑 + 前端交互三重保护
- **权限隔离设计**：RLS 策略实现用户数据完全隔离

### 2. 安全合规
- **符合《个人信息保护法》**：不收集第三方平台数据，所有数据来自用户主动确认
- **数据可追溯**：每条学习记录都有时间戳和用户标识
- **防篡改设计**：数据库触发器防止已完成课程被修改
- **管理端权限**：管理员可查看但不可修改学习记录

### 3. 平台适配
- **基于秒哒平台能力**：所有功能基于秒哒现有组件实现
- **轻量化开发**：无需复杂的第三方集成
- **真实落地**：所有功能可演示、可验证

### 4. 答辩话术
**评委问**：你们的学习时长是怎么统计的？
**回答**：我们采用用户手动确认学习完成机制。由于秒哒平台不支持自动统计学习行为，我们基于课程预设标准时长进行计算。用户完成学习后手动点击"确认学习完成"按钮，系统累加该课程的标准时长。这种方式确保所有数据真实、可追溯、无虚假记录，符合《个人信息保护法》要求。

**评委问**：如何防止用户刷数据？
**回答**：我们设计了三重防护机制：
1. 数据库层面：UNIQUE 约束 + 触发器，防止同一课程重复提交
2. 后端API层面：状态检查逻辑，已完成课程拒绝再次更新
3. 前端交互层面：按钮状态控制，已完成课程按钮置灰不可点击

**评委问**：不同用户的数据如何隔离？
**回答**：我们使用 Supabase 的 Row Level Security (RLS) 策略实现数据隔离。每个用户只能查看和修改自己的学习记录，用户身份由后端 JWT Token 验证，前端无法伪造。管理员拥有特殊权限，可查看所有用户数据但不可修改学习记录。
