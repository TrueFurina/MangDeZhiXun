## 0. 定位定盘（整改的一切都围绕它）

**芒得职训：基于多智能体的大学生软素养对抗式实训引擎**

- 载体：高校就业指导、创新创业通识课的**课内实训**环节
- 主线闭环：**教 → 练 → 评 → 测**（教师发布任务 → 学员对抗实训 → 证据链评估 → 班级学情报告）
- 三个边界：❌ 不做教务管理外壳、❌ 不讲授理论、❌ 不承诺就业结果
- 附属赠品（不进课内主链路、可关闭）：简历助手、自由模拟面试
- 答辩一句话：*"我们不做招聘撮合，我们做高校课堂里的 AI 实训教官。"*

## 3. 方案二：training_tasks / training_submissions 表结构与数据流（P0-2）

### 3.1 设计原则

- 两张表串起"教师发布 → 学员实训 → 证据链评估 → 学情回流"；
- 证据链为核心：不存"一篇静态作业"，存完整对话交互记录（AI 对抗答辩全程）；
- 线上为秒哒 + Supabase（PostgreSQL），DDL 用 PG 语法；主仓 MySQL 仅类型差异（JSONB→JSON/TEXT）。

### 3.2 training_tasks（实训任务表，教师发布）

```sql
CREATE TABLE training_tasks (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  class_id      UUID NOT NULL REFERENCES classes(id),        -- 下发班级
  course_id     UUID REFERENCES courses(id),                 -- 关联课程（就业/双创通识课）
  teacher_id    UUID NOT NULL REFERENCES users(id),          -- 发布教师
  title         VARCHAR(200) NOT NULL,                       -- 任务标题（答辩演示即此标题）
  position_type VARCHAR(50)  NOT NULL,                       -- 岗位类型（见方案五：新文科岗位）
  scenario_type VARCHAR(30)  NOT NULL,                       -- 实训场景：single_interview / group_discussion / defense / jd_stress
  difficulty    SMALLINT     NOT NULL DEFAULT 3,             -- 难度 1-5
  task_config   JSONB        NOT NULL,                       -- 任务链配置（场景剧本/角色/追问策略）
  scoring_rubric JSONB       NOT NULL,                       -- 评分卡（四维：表达逻辑/抗压/冲突沟通/方案拆解）
  publish_date  TIMESTAMPTZ  NOT NULL DEFAULT now(),
  deadline      TIMESTAMPTZ  NOT NULL,
  status        VARCHAR(20)  NOT NULL DEFAULT 'published',   -- published / closed / archived
  created_at    TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_tasks_class ON training_tasks(class_id, status);
CREATE INDEX idx_tasks_course ON training_tasks(course_id);
```

### 3.3 training_submissions（学员实训提交表，证据链核心）

```sql
CREATE TABLE training_submissions (
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  task_id               UUID NOT NULL REFERENCES training_tasks(id) ON DELETE CASCADE,
  student_id            UUID NOT NULL REFERENCES users(id),
  class_id              UUID NOT NULL REFERENCES classes(id),
  interaction_log       JSONB NOT NULL,     -- ⭐ 完整对话交互证据链（AI对抗答辩全程逐轮留存，非最终作业）
  profile_snapshot      JSONB,              -- 实训前画像快照（对比成长用）
  interview_score       JSONB NOT NULL,     -- AI 四维评分 {expression, stress, conflict, analysis}
  final_score           NUMERIC(5,2),       -- 综合成绩（教师可复核调整）
  teacher_remark        TEXT,               -- 教师评语（可选）
  submission_time       TIMESTAMPTZ NOT NULL DEFAULT now(),
  status                VARCHAR(20) NOT NULL DEFAULT 'submitted', -- submitted / graded / appealed
  created_at            TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_sub_task ON training_submissions(task_id, class_id);
CREATE INDEX idx_sub_student ON training_submissions(student_id);
```

### 3.4 数据流（教→练→评→测 全链路）

```
教师端                                 学员端                             回流
┌────────────┐   写入     ┌──────────────────┐    拉取     ┌──────────────────┐
│ 新建班级     │ ───────► │ training_tasks    │ ────────► │ 实训任务列表      │
│ 导入学生     │          │（任务链+评分卡+   │            │（右上角选学号）    │
│ 选岗位/场景  │          │  截止时间）        │            │ → 进入实训        │
└────────────┘          └──────────────────┘            └────────┬─────────┘
                                                                 ▼
┌────────────┐   汇总     ┌──────────────────┐   写入    ┌──────────────────┐
│ 班级学情报告 │ ◄─────── │ 评估Agent出分      │ ◄──────── │ AI对抗答辩（多轮  │
│ 完成率/雷达  │           │ training_submissions│          │  对话证据链留存）  │
│ 导出CSV/PDF │           │（四维评分+证据链）  │          └──────────────────┘
└────────────┘           └──────────────────┘
        │
        ▼ 画像回流
  学生画像更新 → 能力成长树 / 学习计划联动
```

### 3.5 落地注意

| 点 | 说明 |
|---|---|
| 证据链字段 | interaction_log 每轮对话追加 JSON（[{role, content, timestamp, pressure_level}]），是"对抗实训"区别于"静态作业"的答辩铁证 |
| 学号关联 | 学员端"实训任务"页要求"右上角选学号"——student_id 与学号映射在建任务前就位 |
| 班级维度 | 两张表均带 class_id，学情报告按班级聚合，支撑"过程性考核依据"叙事 |
| 秒哒落地 | Supabase 建表 + RLS 行级权限（教师读本班、学员读写本人），四端权限隔离 |

**验收**：教师端发布 1 个任务 → 学员端选学号看到任务 → 完成 AI 对抗答辩 → 教师端班级学情报告出现完成率与四维雷达。

## 6. 方案五：实训内容方向调整（信息安全 → 新文科）（P1-5）

### 6.1 问题实证

线上实训任务页 3 个任务全部网络安全方向：

| # | 现任务 | 场景 | 难度 |
|---|--------|------|------|
| 1 | 安全应急响应模拟：向导师汇报漏洞处置方案 | 技术方案汇报 | 4 |
| 2 | 安全工程师岗位模拟面试（对标奇安信/深信服校招JD） | 项目结题答辩 | 5 |
| 3 | 小组协作：等保测评项目分工协调会 | 群面 | 3 |

首页推荐岗位（AI产品经理·腾讯 22-38K、大模型）、推荐学习资源（深度学习/PyTorch/Kaggle）、测评库（元宇宙/数字孪生/AR-VR 工程师）——全库技术/安全导向，与"新文科"受众错位。

### 6.2 关键洞察

**对抗实训引擎岗位无关**（四维软素养评估通用），只需换内容库的"岗位情境"：网安岗 → 新文科岗。引擎零改动。

### 6.3 新文科目标岗位库

| 方向 | 目标岗位 | 对应软素养维度 |
|------|---------|---------------|
| 内容/新媒体 | 新媒体运营、短视频运营、直播运营、文案策划 | 表达逻辑、内容拆解 |
| 市场/营销 | 市场营销、品牌推广、活动策划、跨境电商运营 | 方案拆解、冲突沟通 |
| 人力/行政 | 人力资源（HRBP/招聘）、行政助理、总助 | 冲突沟通、汇报表达 |
| 产品/运营 | 产品运营、用户运营、客户成功 | 分析拆解、抗压 |
| 教培/服务 | 课程顾问、学习规划师、会务策划 | 表达逻辑、抗压 |
| 数字化基础 | 业务数据分析（Excel/SQL 基础）、电商运营 | 方案拆解、数据表达 |

### 6.6 答辩叙事衔接

> "我们的对抗实训引擎是岗位无关的，但首期内容库聚焦新文科——因为新文科学生最缺的不是知识，是表达、抗压、协作这些课堂里练不到的软素养。实训任务全部来自真实校招 JD 拆解，教师一键下发到班级，完成即生成四维能力证据链。"

### 6.7 实施顺序（2-3 天）

1. 替换 3 个实训任务 + 新增 3 个（半天，最高优先——答辩演示直接可见）；
2. 首页推荐岗位/学习资源换新文科口径（半天）；
3. 测评题库新增新文科岗位（1 天，可分批）；
4. 行业标准库补充软素养标准（半天，可后置）。

**验收**：实训任务页任务标题全部新文科情境（新媒体/电商/营销/行政/三创答辩），无"漏洞/等保/渗透"字样；首页岗位/资源同口径。
